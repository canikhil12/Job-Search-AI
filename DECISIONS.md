# Design Decisions

Format: `decision — why — interview talking point`

- Java records for all DTOs (no Lombok) — records give immutable, boilerplate-free data carriers built into the language — talking point: records replace Lombok's `@Value` for DTOs with zero dependencies and a smaller attack/maintenance surface; Lombok's annotation processing can fight newer JDKs.
- UUID primary keys generated in the app (`UUID.randomUUID()`) with `gen_random_uuid()` as the DB-side default — app-side generation keeps the id available before the row is flushed and avoids a DB round-trip, while the SQL default protects direct inserts — talking point: know the tradeoff vs auto-increment (no sequence contention, opaque ids, but 16 bytes and non-monotonic index inserts).
- `gen_random_uuid()` instead of the `pgcrypto` extension — it is built into PostgreSQL 13+ — talking point: one less extension to provision; `pgcrypto` is only needed on older Postgres.
- `pgvector` extension enabled in V1 despite being unused in Phase 1 — the production DB (Neon) will store embeddings for semantic matching, and enabling it up front keeps migrations forward-only — talking point: Flyway migrations are immutable once applied, so provisioning the extension early avoids a schema-drift headache later.
- Stateless JWT with access token only (no refresh token yet) — simplest thing that works for a portfolio API; refresh rotation is a later phase — talking point: be ready to explain access/refresh split and rotation.
- Fail-fast on missing/short `JWT_SECRET` (< 32 bytes) at `JwtService` construction — HS256 needs a 256-bit key or JJWT throws `WeakKeyException`; failing at startup beats failing on the first login — talking point: fail-fast config validation surfaces misconfiguration in deploy, not in production traffic.
- `ddl-auto: validate` with Flyway owning the schema — the DB schema has a single source of truth (SQL migrations), and Hibernate only checks the entity mapping matches — talking point: never let Hibernate `update`/`create` a production schema; migrations are auditable and reversible-by-forward-migration.
- Custom `AuthenticationEntryPoint` returns the same `ApiError` JSON shape as `GlobalExceptionHandler` — clients get one consistent error contract whether the failure is auth or application-level — talking point: consistent error envelopes simplify frontend error handling.
- JWT stored in localStorage (+ in-memory) — simplest approach for a stateless API portfolio project — talking point: XSS can read localStorage, so production hardening would use an httpOnly SameSite cookie with CSRF protection, or short-lived access tokens with refresh rotation; be ready to compare the tradeoffs.
- CORS config AND Vite dev proxy both present — the proxy makes local dev same-origin (browser never sends a cross-origin request), so CORS only matters in production where Vercel (frontend) calls Render (backend) cross-origin — talking point: know which mechanism is active in which environment and why removing either breaks exactly one of them.
